## Task 8: Video thumbnail extraction in queue items

**Files:**
- Modify: `src/VideoTriage.App/ViewModels/FileItemViewModel.cs`
- Modify: `src/VideoTriage.App/ViewModels/MainViewModel.cs`
- Modify: `src/VideoTriage.App/Views/MainWindow.xaml`

### Context

`VideoStats.AttachedPicStreamIndex` (added in Task 7) carries the global ffprobe stream index of
the embedded poster. When it is non-null, `ffmpeg -map 0:{index} -frames:v 1` extracts just
that stream — no video decoding, just a copy of the already-compressed image. Files with no
attached picture skip the ffmpeg call entirely.

The extraction is fire-and-forget async: dispatched after the probe result populates the row.
`BitmapCacheOption.OnLoad` + `Freeze()` makes the bitmap safe for cross-thread dispatch.
`DecodePixelWidth = 96` limits memory usage to the display size. Failures leave `Thumbnail` null
and the grey placeholder background shows through.

Add the following private method to `MainViewModel` before the `InlineProgress` nested class

```csharp
private async Task ExtractThumbnailAsync(FileItemViewModel row, string filePath, int streamIndex)
{
    var temp = Path.Combine(Path.GetTempPath(), $"vt_thumb_{Guid.NewGuid():N}.png");
    try
    {
        using var proc = new Process();
        proc.StartInfo = new ProcessStartInfo
        {
            FileName = "ffmpeg",
            Arguments = $"-i \"{filePath}\" -map 0:{streamIndex} -frames:v 1 -loglevel quiet \"{temp}\" -y",
            CreateNoWindow = true,
            UseShellExecute = false
        };
        proc.Start();
        await proc.WaitForExitAsync();

        if (proc.ExitCode == 0 && File.Exists(temp) && new FileInfo(temp).Length > 0)
        {
            using var memStream = new MemoryStream(File.ReadAllBytes(temp));
            var bitmap = new BitmapImage();
            bitmap.BeginInit();
            bitmap.CacheOption = BitmapCacheOption.OnLoad;
            bitmap.StreamSource = memStream;
            bitmap.DecodePixelWidth = 96;
            bitmap.EndInit();
            bitmap.Freeze();
            _dispatcher.Post(() => row.Thumbnail = bitmap);
        }
    }
    catch
    {
        // Thumbnail extraction is best-effort; failures leave Thumbnail as null
    }
    finally
    {
        try { File.Delete(temp); } catch { }
    }
}
```

## Task 9: Truncate long filenames and filter non-candidate files from the queue

**Files:**
- Modify: `src/VideoTriage.App/Views/MainWindow.xaml`
- Modify: `src/VideoTriage.App/ViewModels/MainViewModel.cs`

### Context

Two issues with the queue display:

**1. Filename overflow.** The queue item template has three columns: thumbnail (96 px fixed),
file info (`*`), status (180 px fixed). The filename `TextBlock` in the middle column has no
trimming, so very long names overflow visually and can cover the status text on the right.
Fix: `TextTrimming="CharacterEllipsis"` tells WPF to truncate with "…" when the text doesn't
fit the available column width.

**2. Non-candidate files shown after scan.** `FolderProbeScanner` classifies every file and
reports it via `IProgress<ProbeResult>`. `MainViewModel.ChooseFolderAsync` currently adds all
results to `Items` regardless of classification outcome. Files classified as `SkipLowBpp`
("Below threshold"), `SkipAlreadyAv1`, or probe failures clutter the queue with entries that
will never be processed. Fix: skip the `Items.Add` call for any result whose
`Classification.Outcome` is not `ClassificationOutcome.Candidate`.

Note: Task 8 adds the thumbnail extraction call after `Items.Add`. The filter step in this task
must come **before** that call (i.e. after the filter guard, not before it), so it also
naturally skips thumbnail extraction for non-candidates.

### Steps

- [ ] **Step 1: Add TextTrimming to the filename TextBlock**

In `src/VideoTriage.App/Views/MainWindow.xaml`, find the filename `TextBlock` inside the queue
item `DataTemplate` (approximately line 215):

```xml
<TextBlock Text="{Binding FileName}"
           FontWeight="SemiBold" />
```

Replace with:

```xml
<TextBlock Text="{Binding FileName}"
           FontWeight="SemiBold"
           TextTrimming="CharacterEllipsis" />
```

- [ ] **Step 2: Filter non-candidate results in ChooseFolderAsync**

In `src/VideoTriage.App/ViewModels/MainViewModel.cs`, find the `IProgress<ProbeResult>`
callback body inside `ChooseFolderAsync` (approximately line 150):

```csharp
var progress = new InlineProgress<ProbeResult>(result =>
    _dispatcher.Post(() =>
    {
        var row = new FileItemViewModel(result.FilePath);
        row.ApplyProbe(result);
        Items.Add(row);
        if (result.Stats?.AttachedPicStreamIndex is { } streamIndex)
            _ = ExtractThumbnailAsync(row, result.FilePath, streamIndex);
    }));
```

Replace with:

```csharp
var progress = new InlineProgress<ProbeResult>(result =>

    {
        if (result.Classification?.Outcome != ClassificationOutcome.Candidate)
            return;
        var row = new FileItemViewModel(result.FilePath);
        row.ApplyProbe(result);
        Items.Add(row);
        if (result.Stats?.AttachedPicStreamIndex is { } streamIndex)
            _ = ExtractThumbnailAsync(row, result.FilePath, streamIndex);
    }));
```

`ClassificationOutcome` is in `VideoTriage.Core.Models`, which is already imported in
`MainViewModel.cs`.
